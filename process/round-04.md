- [x] 1. Nav sidebar — remove the legacy Explorer panel, replace with a module browser classified by kind (v3-aware, counts every module)
  - **Root cause investigated first, not assumed**: `explorer.js`'s `api.wiki.explorerTree` (`src/db/wiki.js`) queried exclusively the 5 legacy fixed-module table families (Scribe/Director/Navigator/Hero/Writer) — it never touched the v3 `module` table, so in a fresh v3-only vault (the common case) every section rendered empty. It also seized `#left-panel-inner` via a full `innerHTML` overwrite, meaning opening it *replaced* the v3 Hub's Nest/Sage Hut/Import Dock accordion rather than living alongside it.
  - Replaced with a 4th accordion section in the Hub itself (`buildKindBrowserHtml`, `hub.js`) rather than another panel-swapping rail button — sits between Nest and Sage Hut. Data source is `S.moduleTree` (already loaded per-Nexus, zero new IPC) flattened recursively (`flattenModulesByKind`) and grouped by `.kind` (`groupModulesByKind`) — every module counted, including `collector` (folder-like) modules, satisfying "count every module." Only kinds actually present in the Nexus render a row (icon, color, label, count), each expandable (`toggleKindGroup`) to an alphabetical flat list of that kind's modules; clicking a module calls `openModuleNode(id)` — the same entry point the Nest tree itself uses, no new navigation path invented.
  - Reused existing styled classes throughout (`.li`/`.kicon`/`.name`/`.tree-chev`/`.indent1` from `buildNestRow`'s precedent) — zero new CSS needed. The count badge deliberately reuses the `.li .kind` class (a small right-aligned bordered pill) rather than `.cnt`, since `.cnt` has no generic unscoped style in `style.css` (only scoped variants elsewhere) while `.li .kind` already is one — accepted the slightly odd class-name-vs-content mismatch over inventing new CSS for a pill that already exists.
  - **Full, verified-clean removal** (grepped the whole repo including `flutter_app/` — zero references there): deleted `explorer.js` outright; removed its rail button (`index.html`), `openExplorer()` and the `.explorer-btn` visibility toggle (`core.js`), the `wiki:explorerTree` preload entry and main.js IPC handler, the `explorerTree()` function and its `module.exports` entry (`src/db/wiki.js` — confirmed sole caller was `explorer.js`), the `.xp-*` CSS rule block (`style.css`), and the `explorer:` i18n key (replaced 1-for-1 with `kindBrowser:` at the same position in all 18 locale blocks, since it had exactly one call site, now gone). `S.explorerOpen`/`S.explorerTree` state replaced with `S.kindBrowserOpen` (session-only, not persisted — consistent with other in-session accordion Sets).
  - Live-verified via `run-dracondex` against real Electron: created a test Nexus with 3 modules across 2 kinds (2 Sketcher, 1 Manager), confirmed the new "เรียกดูตามประเภท" section renders with correct per-kind counts (`Manager 1`, `Sketcher 2`), expanding a kind group lists its modules alphabetically, clicking a module opens it (`S.activeModuleNode.name` confirmed), and `document.querySelector('.explorer-btn')` returns `null`.
  - Docs flagged for the standard `write-docs` follow-up, not done this pass: `docs/SYSTEMS.md` §2d "IDE Shell" (Explorer bullet), `docs/FILES.md`'s `explorer.js` row, `docs/Architec.md`'s Explorer/`wiki:explorerTree` mentions. `docs/CHANGELOG.md`'s historical v2.8 entry describing Explorer was deliberately left untouched — it's a record of the past, not current-state documentation.
- [x] 2. Builder tab bar — move the split-pane buttons away from the confusingly-adjacent Module Inspector toggle
  - **Confirmed with the user**: a cheap in-row reorder (no new overflow/context menu). `builderPaneHeadHtml`'s single flexible child (`.bpane-tabs{flex:1}`) was already doing all the layout work — the fix was purely reordering the returned template string so `splitBtns` sits next to the back/forward nav buttons (far left) instead of next to `inspectorToggle` (far right), leaving the inspector toggle alone at the right end. Zero new markup or CSS; `splitBtns`/`inspectorToggle` themselves are byte-for-byte unchanged, only their position in the concatenated string moved.
  - Deliberately out of scope: `nav`/`splitBtns` still use raw Unicode glyphs (`◀`/`▶`/`◫`/`⬓`) rather than `I.*` SVGs — a pre-existing `STYLE.md` inconsistency unrelated to this position-only fix, not touched.
- [x] 2.1. Change the Module Inspector toggle's icon to a mirrored "hub toggle" style
