## Part 1 — user manual test: fix part UI (hub toggle button, nav sidebar)
Files: `electron/css/titlebar.css`, `electron/css/nav-hub.css`, `electron/index.html`, `electron/src/renderer/core/{state.js,ui.js,boot.js}`

- [x] Hub toggle btn — investigated before fixing rather than assuming "the title slides over it": root cause was `#title-left-zone` shrinking to `calc(var(--nav) + 1px)` on collapse while `.tab-brand` alone is a fixed 44px with `flex-shrink:0` — with `overflow:hidden` on the parent, everything after the brand (the toggle button, the vault-name span) simply fell outside the visible box and got clipped. `#builder-tabs` (a flex sibling, not an overlapping element) then naturally shifted left into the space the shrunken zone stopped reserving, which is what read as "the title moving over it." Fixed with a `#title-tab-bar.left-panel-collapsed` CSS block that fades out `.tab-brand`, hides `#titlebar-vault`, and absolutely-positions `#hub-toggle-btn` into the brand's old 44×38 slot — so the toggle visually replaces the icon and stays clickable, per Plan.md's own literal fix description ("slide the toggle btn to overlap/replace the icon"). CSS-only; the existing `applyLeftPanelState()` class toggle already drives it, no JS change needed.
- [x] Nav side bar — buttons (40×40px) left almost no margin inside the 42px-wide rail. Bumped `#nav-sidebar`'s `padding`/`gap` (2px 0/6px → 6px 0/10px) and switched `.nav-logo-btn`/`.nav-btn` from fixed `40px`/`40px` to `width:70%;aspect-ratio:1;height:auto` so they scale with the rail's current width automatically (`.nav-logo-btn .brand-img` scoped to `70%`/`70%` so the logo image doesn't overflow at the new smaller size).
  - Added a 4th instance of this repo's existing drag-to-resize pattern (mirrors `startLeftPanelResize`/`startPageViewResize`/`startHubSectionResize`, all `core/ui.js`): new `#nav-sidebar-resize` handle (`index.html`), `startNavRailResize` writing `--nav` via `applyNavRailWidth()`, clamped `[34,80]`px, persisted to a new `novel-manager-nav-rail-width` localStorage key (`core/state.js`), restored on boot (`core/boot.js`).
  - Live-verified via `run-dracondex`: hub-toggle button confirmed visible and clickable in both collapsed and expanded states (screenshotted); nav rail buttons confirmed visibly smaller with real margin at default width; drag-resize confirmed live (`--nav` 42px→80px via a simulated mousedown/mousemove/mouseup sequence), and the resized width confirmed to persist across a real app relaunch (`localStorage` + `applyNavRailWidth()` on boot).

**Part 1 complete** — both items shipped and live-verified.

## Part 2 — setting window (sizing/advance, module-name compare list, tool-toggle preview, always-open sidebar, @LDKTC plugin list)
Files: `electron/src/renderer/core/{setting-window.js,settings.js,tool-toggle.js,welcome.js}`, `electron/src/renderer/plugin.js`, `electron/src/db/plugin.js`, `electron/main.js`, `electron/preload.js`, `electron/css/{components.css,nav-hub.css}`, `electron/src/renderer/i18n.js`

- [x] Sizing advance — new shared `sliderNumberRowHtml()` helper (`setting-window.js`) renders a slider+number pair in one row (`.size-slider-row`, CSS grid `5fr 1fr`) for all 5 Advanced-reveal rows (UI size %, font size %, and the 3 per-area scale rows). Live sync is pure DOM — `oninput` on either control writes straight to its sibling's `.value` — while `onchange` still calls the exact same setter each row already used (`setAreaScale`/`setUiSetting`), so persistence is unchanged; only the row markup changed.
- [x] Max version (`versionLimit`) — pulled out of the collapsible `S.settingAdvanced` block and placed unconditionally right after the Advanced toggle button, so it's visible whether or not Advanced is expanded (Plan.md's literal ask: "move it outside, appended after the advance button").
- [x] Module name — new read-only `nameModeCompareListHtml()` (`settings.js`), modeled on the first-run wizard's existing dual-list picker (`welcomeStepNamesHtml`, `welcome.js`) but with the `onclick`/active-state stripped, since **user's explicit call** (asked via `AskUserQuestion` mid-plan): keep the existing 2-button Unique/Classic toggle as the only thing that switches `nameMode`, and add the dual list below it purely as a side-by-side comparison view. Reused `welcome.css`'s `.welcome-name-*` classes through a new `.setting-name-cols` scope (own `--wz-name-row` var since the original is scoped under `.welcome-wizard` only; relaxed hover/cursor styling since nothing here is clickable; `max-height:clamp(4 rows, 26vh, 5 rows)` — the Setting window itself is a fixed-size floating panel, not user-resizable, so the "4-5 rows depending on window size" spec was implemented as a viewport-height-driven clamp rather than a JS resize-observer). Generalized `welcomeSyncNameScroll()` to find its sibling list by DOM position (`closest('.welcome-name-cols')`) instead of the old hardcoded wizard element ids, so one function now serves both the wizard and this new Settings view.
- [x] Tools switch — confirmed by reading the code first, rather than assuming a gap existed: toggling a nav/status setting already applies live to the real, on-screen nav-sidebar button/status bar behind the Setting window, because the Setting window is a modeless `.floating-panel` by original design (centered, not full-viewport, specifically so the app underneath stays visible and interactive). Added a small `.tool-toggle-flash` outline-pulse (`nav-hub.css`) fired via a new `flashEl()` helper at the end of `toggleNavSetting`/`toggleStatusSetting` (`tool-toggle.js`), so the already-live change is unmissable rather than only noticeable if the user happens to be looking at the right spot.
- [x] Session head — `settingWindowNavHtml()` (`setting-window.js`) no longer gates each group's `.setting-nav-pages` list behind `openGroup`; every group's page list now renders always-open (no more single-open accordion). The group header (`.setting-nav-head`) lost its `onclick`/cursor-pointer/hover styling since there's nothing left for a click there to toggle — page selection is solely through the `.setting-nav-item` buttons underneath it now.

Filters out `is_template`/`archived` repos, satisfying Plan.md's "except repo template" without hardcoding a repo name. Advisory/silent on failure (offline, rate-limited) — no error toast, matching the existing silent auto-preview-on-type convention in the same file.
