## Part 1 — UI/UX pass: interaction defects (2026-07-25)

Uncommitted at the time of this write-up; committed together with this close-out. The audit behind this part found two distinct classes of problem — interaction defects that were silently wrong (this part), and visual-system debt (Part 2). Scope was set with the user up front: **UX first, then visual, surgical** (fix what is actually broken, do not restyle), with Thai typography explicitly in scope.

Files: `src/renderer/core.js`, `src/renderer/search.js`, `src/renderer/quickswitch.js`, `src/renderer/hub.js`, `src/renderer/hashtag.js`, `src/renderer/writer.js`, `src/renderer/navigator.js`, `src/renderer/hero.js`, `src/renderer/i18n.js`, `main.js`, `preload.js`, `index.html`, `style.css`.

- [x] 1.1 **`toast()` type aliasing.** 20 call sites across 11 files passed `toast(msg,'error')`, but `style.css` only ever defined `#toast.ok`/`#toast.err` — every one of those error messages rendered as neutral gray, visually indistinguishable from a success toast. Fixed inside the helper with a `TOAST_CLS` map (`error→err`, `success→ok`) rather than editing 20 call sites, which also stops the spelling drifting again. `#toast` gained `role="status"`/`aria-live="polite"`.
- [x] 1.2 **Modal Escape + first-field focus.** `#modal-overlay` bound only its ✕ and a backdrop click, and `bindGlobalShortcuts` early-returns on non-modifier keys — so the main modal was the one overlay in the app where Escape did nothing (`uiConfirm`, `quickswitch`, `guide` all handled it). New `bindModalEscape()` listens in the **bubble** phase precisely because those three listen in capture and stop their own event, so whichever is stacked on top wins naturally; guards additionally check for `#confirm-overlay`/`#qs-overlay`/`#guide-overlay` and for a hidden `#modal-close`, the last one preserving the first-run welcome modal (which hides its ✕ deliberately because picking an option is required). `openModal()` now focuses the first `input`/`textarea`/`select` in `#modal-body`, falling back to today's `#modal`; the ~15 existing per-caller `setTimeout(...focus(),60)` lines were left alone — they became redundant, not wrong.
- [x] 1.3 **Confirms on 7 destructive deletes.** `deleteCustomTheme` (`core.js`, worst of the set — a hover-only `×` destroying a hand-tuned 10-token palette with no undo), `deleteColorSwatch`, `deleteWriteWordLink`, `removeCharLink`, `removeEventObject`, `deleteGameConv`, `deleteHeroAttrLevel`. All 7 call sites are `onclick=` handlers with no return value relied on, so the `async`-ification is safe. The map's own delete **tool** (`navigator.js`, which deletes on a single canvas click by design, calling `api.world.removeEventObject` directly rather than through the wrapped function) was deliberately excluded — a per-click confirm there would be worse than the problem.
- [x] 1.4 **Native `prompt()` removed.** `importCustomPalette` still used `prompt()` — the exact native-dialog class whose Electron renderer-input-freeze bug is what `uiConfirm` was written to fix (its own code comment says so). Replaced with a new `uiPrompt(msg, opts)` → `Promise<string|null>`, built as a deliberate sibling of `uiConfirm`. **Design decision worth recording**: it is built on the `#confirm-overlay` chrome, not `openModal`, because `#modal-overlay` is `z-index:100` while `.floating-panel` (the custom-theme editor that raises this prompt) is `150` — a modal would have rendered *behind* its own caller. `#confirm-overlay` sits at 1000 and clears every layer. Esc cancels, Ctrl/Cmd+Enter submits (plain Enter inserts a newline, since the field is multi-line for pasted JSON).
- [x] 1.5 **Sidebar search stopped destroying the Nest tree.** Two defects, one fix. `renderSearchResults()` `innerHTML`s `#left-panel-inner` — which under v3 **is** the Nexus Nest tree — so typing in the search box wiped the module tree out of the sidebar; and `api.search.all` only covers legacy projects/objects/hashtags, finding nothing in the v3 module tree anyway. Meanwhile `openQuickSwitcher()` already did fuzzy search over the merged viewer+wiki pool with scope chips, kind filter, backlink counts and breadcrumbs — and was reachable *only* by Ctrl+P, with no button, menu item or hint anywhere in the UI. `bindSearch` now hands off to `openQuickSwitcher(seed)` whenever a vault is open (clearing its own field), and keeps the legacy inline path untouched when there is no `S.nexus`. `openQuickSwitcher` gained an optional `seed` parameter that pre-fills `#qs-input`, runs the first filter pass, and puts the caret at the end so the seeded text reads as already-typed. The `(Ctrl+P)` hint went into `translateStaticChrome()` rather than `bindSearch`, because that function already owns this placeholder and re-runs on language change.
- [x] 1.6 **Keyboard-shortcut help + replayable tour.** Ctrl+P/W/Tab/N/E appeared nowhere in the UI, and `guide.js`'s 5-step coach marks fired from exactly one place (the welcome modal's tour checkbox) with no way to see them again. Added a help group to the settings dropdown: `openShortcutsModal()` (driven by a `SHORTCUT_HELP` table, key names marked `data-no-i18n`) and `replayGuideTour()`. The guide already skips steps whose target is absent, so replaying from an arbitrary app state is safe. Entry function is `startNexusGuide`, not `startGuide` — confirmed against `guide.js` rather than assumed.
- [x] 1.7 **Nest empty states got a CTA.** `buildNestTreeHtml` and `buildKindBrowserHtml` rendered a text-only `.empty` even though `openMajorModuleModal` existed, so a brand-new vault was a dead end — the only way forward was a `+` tucked into the rail/accordion header. Factored a small `nestEmptyHtml()` used by both. Deliberately did **not** build a shared empty-state helper: that pattern is copy-pasted across 126 call sites and refactoring it is a separate job.
- [x] 1.8 **Loading feedback.** The renderer had no spinner, skeleton or `aria-busy` anywhere. Added one `setBusy(el, on)` helper plus `.busy-veil`/`.busy-spin`/`.busy-text` CSS (theme tokens only, with a `prefers-reduced-motion` slow-down), applied to the two worst offenders only: `openModuleNode` (awaits several IPC loads after the shell is already painted, so a click on a large module looked like it did nothing) and `chooseImportAsNexusNest` (an unbounded N×M migration loop previously guarded only by `pointerEvents:none`). Both wrapped in `try/finally`.
- [x] 1.9 **Import DB confirm moved after the file picker — required splitting the IPC.** `importDatabaseFile` asked `uiConfirm` *before* calling `api.db.importFileMerge()`, so the user approved a merge before choosing what to merge. **The plan's original assumption was wrong and reading `main.js` caught it**: `db:importFileMerge` opened the dialog *and* ran `db.importDatabaseMerge()` in the same atomic handler, so simply reordering would have confirmed a merge that had already happened. Split into `db:pickImportFile` (dialog only → `{canceled, filePath}`) and `db:importMergeFile(path)` (the actual merge), wired through `preload.js`. The `db` namespace is not in `IMPORT_DB_READONLY_NS`, so the read-only guard needed no change. The two hardcoded Thai strings in that function moved to `t()` keys.
- **16 new i18n keys × 18 locales** (`confirmDeleteTheme`, `confirmDeleteItem`, `confirmRemoveLink`, `apply`, `help`, `shortcuts`, `replayTour`, `scQuickSwitch`, `scCloseTab`, `scNextTab`, `scPrevTab`, `scNewNote`, `scToggleEditor`, `loading`, `importDbConfirm`, `importDbDone`) — inserted by a one-shot script anchored on each locale's opening line, then the whole file parse-checked.
- **Bug found by live testing, not by reading the diff**: with everything above in place, one Escape press closed *both* a stacked `uiConfirm` and the modal underneath it. Root cause: `uiConfirm`'s key handler called `preventDefault()` but never `stopPropagation()`, and `finish()` removes the overlay synchronously — so the same event went on to reach `bindModalEscape`, whose "is a confirm on top?" guard by then saw an already-detached overlay. Fixed at the source by adding `stopPropagation()` to `uiConfirm` (and `uiPrompt`), matching what `guide.js` and `quickswitch.js` already did; `uiConfirm` was simply the odd one out. Re-verified: first Escape closes only the confirm, second closes the modal.
- **Verified live via `run-dracondex`, real Electron, this session**: Escape ignored on the required welcome modal (`eval` → modal still open); `openModal` autofocus (`document.activeElement.id` → `"nx-name"`); empty-state CTA present after creating a vault; `toast('boom','error')` → class `show err`, computed `border-color: rgb(239,68,68)`; sidebar search → quick switcher opened seeded with `"Vault"`, `#search-input` cleared, **and `#left-panel-inner` still held the Nest tree**; shortcuts modal rendered 6 rows in Thai and closed on Escape; stacked-overlay Escape behaviour re-checked after the fix; `uiPrompt` and the busy veil screenshotted (`aria-busy="true"` set).
- `node .claude/skills/dracondex-module-style/check.mjs` held at the **0 errors / 31 warnings** baseline throughout. Two self-inflicted regressions were caught by diffing against a stashed baseline and fixed before moving on: a hex literal in the new `uiPrompt` placeholder string (tripped the hardcoded-color rule) and an undefined `.busy-text` class.

**Part 1 complete** — all 9 items shipped and live-verified via `run-dracondex`.

## Part 2 — UI/UX pass: visual system, surgical (2026-07-25)

Files: `style.css` (the bulk), plus a mechanical `--fsc` sweep across 16 renderer files.

Ordering mattered here and was followed strictly: every no-op step landed before the one step that changes pixels, so a regression would stay bisectable.

- [x] 2.1 **Token hygiene.** Declared `--fsc:1` in `:root` — it was referenced 300+ times as `var(--fsc,1)` but never declared anywhere; `core.js` sets it inline on `documentElement`, which still wins, so declaring it is provably a no-op and simply makes the token real to anyone reading `:root`. The 306 `,1` fallbacks were deliberately **not** stripped (300+ edits, zero benefit). Deleted dead `--bg3` (declared on `body`, zero consumers) and amended its comment; kept `--bg2` (3 consumers). Decided **not** to add `--button` to the 19 themes missing it — it is always consumed as `var(--button, var(--accent))`, so adding 19 lines of `--button: <same as accent>` would be pure noise; documented in `:root` instead. `--ui-scale` is likewise unconsumed in CSS but written by `core.js`, so it was kept and annotated rather than removed.
- [x] 2.2 **Missing scales added (declarations only).** `--sp-0..7`, `--fs-micro..xl`, `--lh-*`, `--shadow-pop/float/menu/modal`, `--mono`. Values are the **measured modes of the existing file**, not invented, so new code matches the existing rhythm instead of introducing a second one. The `--fs-*` tokens bake in `calc(Npx * var(--fsc,1))` so new code structurally cannot repeat the bypass fixed in 2.7. The ~2,200 existing px literals were explicitly not retrofitted.
- [x] 2.3 **Shadow retrofit, exact matches only.** 12 `box-shadow` declarations whose values were byte-identical to one of the 4 new tokens, replaced via literal string split/join anchored on the `box-shadow:` prefix so the `:root` declarations themselves could not be rewritten. The 4 near-miss values (e.g. `0 24px 60px rgba(0,0,0,.5)`) were left alone — folding those into a token *is* a look change, however small, which the surgical constraint excludes.
- [x] 2.4a **`--on-accent`/`--on-button`/`--on-danger`/`--ink-dark` introduced; 28 `#fff` swapped.** `#fff` was hardcoded as "ink on a filled surface" across a stylesheet where 32 themes set `--accent` freely. Each `#fff` was classified by reading what its rule's fill actually is, not by pattern-matching: 20 on `var(--accent)`, 2 on `var(--button, var(--accent))`, 4 on `var(--danger)`, and **2 genuine bugs** where the fill is `var(--hover)` and white text was invisible on all 8 light themes (`.dark-table tbody tr.active td` → `var(--t1)`, `.btn-g:hover .icon-danger` → `var(--danger)`). 9 were left as literal white on purpose — they paint against *user-chosen* colors or arbitrary hues (`.graph-label`, `.rel-node`, `.map-point`, the color wheel, `.chr-cal-ev`). Applied by a line-targeted script that asserts each line still contains `#fff` before rewriting and that none remains after, so a shifted line fails loudly instead of being silently rewritten. All three tokens default to `#fff`, making this step computed-value-identical in every theme. **They are three independent literals on purpose** — `--on-button:var(--on-accent)` would hit the exact aliasing trap the existing `--bg2` comment documents, where a per-theme override never reaches the alias.
- [x] 2.4b **Per-theme overrides — the one step that changes pixels.** Contrast was recomputed independently (WCAG relative luminance, white vs each theme's `--accent` and its effective button fill) rather than trusting the planning numbers; the result matched exactly. Overrode to `--ink-dark` in **15 themes for `--on-accent`** and **12 for `--on-button`**, threshold 3:1. Verified before applying that **no flip makes contrast worse**. **Two tokens are genuinely required, not one**: `blueEclipse` has `--accent:#191970` (14.85 against white — white is correct) but `--button:#c9ccd4` (1.61 — white unreadable), so a single token could not express it. Its pre-existing one-off patch (`.btn-p,.modal-actions button{color:#1a1a26}`) was removed, since it was correcting the `--button` fill via per-component selectors and would otherwise have double-applied and outlived the `.modal-actions` deletion in 2.6. **Deliberately not done**: `--on-accentH`. 25 of 32 themes fail 3:1 against the lighter `--accentH` hover fill, but fixing it means either flipping `.btn-p` ink in 25 themes or making the label color flicker on mouseover — the real defect is that `--accentH` is a *lighter* hover on a filled button, which is a restyle, not a defect fix.
- [x] 2.5 **Thai typography.** Thai is the app's default UI language but no Thai-capable face was named in the stack. Inserted `'Leelawadee UI', Tahoma` **after** `'Segoe UI'` — which covers Latin/Greek/Cyrillic completely, so the additions are only ever reached for codepoints it lacks and **no Latin glyph changes**; the emoji/symbol faces stay in positions 1–2 because emoji are used as icons throughout. Both ship with Windows and the build targets are win/nsis only, so no webfont or vendored file is involved. Replaced `word-break:break-word` with `overflow-wrap:break-word` at 4 long-text surfaces: the former is spec-defined as `overflow-wrap:anywhere`, which suppresses Blink's ICU dictionary Thai segmenter and breaks mid-syllable (Thai has no inter-word spaces); the latter still contains long unbreakable URLs, the original intent. **Line-height was measured, not bumped**: `th` is the default locale, so a global `html[lang="th"]` bump would reflow the app's default appearance. All 13 `line-height:1` sites were inspected and every one renders only emoji, symbols or numerals — the three flagged during planning as "can hold translated Thai" turned out to be the ✕/+/x glyph buttons. Correct outcome was therefore **zero line-height edits**.
- [x] 2.6 **Dead CSS removed.** 12 compat-layer classes with **zero** consumers anywhere in `src/` or `index.html` (verified by raw substring grep, which also catches `classList.add`/`className`/template-literal usage, not just `class="..."`): `.panel-item`, `.ph-add`, `.detail-header`, `.detail-actions`, `.section-head`, `.desc-card/-title/-content/-actions`, `.tag-picker`, `.btn-xs`, `.modal-actions`. Plus a block that re-defined `.empty h3/p`, `.tag`, `#toast` and the 4 scrollbar rules verbatim a few lines below their originals. **`.btn-xs` could not be deleted line-wise** — it shared two `.danger` selector lists with `.btn-sm` (20 consumers), so those selectors were trimmed first. Classes that *look* similar but are live were confirmed kept (`.btn-sm` 20, `.form-row` 17, `.detail-head` 7, `.tag-chip`, `.tab-btn`, `.pick-list/-item`, `.btn-danger`, `.link-chip`). The planning note claiming `.note-section`/`.detail-tags` were duplicated was a **false positive** — those are complementary box vs. flex-`order` rules, deliberately split — and were left untouched. Brace balance re-checked (1337/1337) after the deletions.
- [x] 2.7 **`--fsc` bypass sweep.** 126 inline `font-size:Npx` across 16 renderer files did not scale with the font-size accessibility setting (which clamps to 80–130%). Rewritten to `font-size:calc(Npx * var(--fsc,1))`, which at 100% computes to exactly the original px — so the diff is a provable no-op at default settings. A class-per-size approach was rejected (≈15 new utility classes *and* still editing all 126 sites, each a checker-warning risk); a JS helper was rejected because the sizes sit inside mixed declaration strings. Confirmed safe before running: SVG uses the unitless presentation-attribute form, which a `px`-anchored regex cannot match; there are no `ctx.font` canvas assignments; the 27 `em`/`rem`/`%` values already scale via `body{font-size:calc(14px*var(--fsc,1))}`. Piloted on `director.js` (10 sites) before the rollout, and every renderer file `node --check`ed afterward.
- **Verified live via `run-dracondex`, real Electron, this session.** The strongest evidence is a **measured** one rather than a visual one: a probe injected `.btn.btn-p` and `.nav-btn.active` elements, switched through all 32 themes, and computed the real WCAG contrast from `getComputedStyle`. Result: **zero failing themes**; worst button contrast 1.61 → **3.19**, worst nav 1.67 → **3.53**; and the untouched themes still measured exactly their pre-change values (daylight 5.17, midnight 4.47, redEclipse 3.87), confirming 2.4a was value-identical for them. **A measurement bug was caught and fixed mid-verification**: the first probe reported an identical 5.17 for every theme, because Chromium caches computed style per element within one synchronous task, so reusing a single probe across theme switches reports the *first* theme's colors throughout — fixed with fresh elements plus a forced layout read per iteration. Also screenshotted `clearMeteor` (amber accent, now dark ink), `clearSky`, and `blueEclipse` (which correctly shows dark ink on its light button while keeping white on its dark-navy nav — the split case). Font scale checked at 80/100/130%: a swept inline `font-size` measured 12px at 100% and **15.6px at 130%**, confirming the bypass is gone; no clipping or overflow at 130%, Thai tone marks intact. `.dv` confirmed as `overflow-wrap: break-word` / `word-break: normal` with `Leelawadee UI` present in the resolved font stack.
- `check.mjs` held at **0 errors / 31 warnings** after every step, and a final `--fresh` end-to-end run (create vault from the welcome modal) completed clean.

**Part 2 complete** — all 7 items shipped and verified across 32 themes and 3 font scales.

**`Plan.md` rollout complete** — Parts 1 and 2 of the UI/UX pass both shipped and live-verified via `run-dracondex`.
