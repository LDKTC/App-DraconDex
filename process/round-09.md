## Part 6 — Obsidian-style module filter overhaul, filter/tag-link modals → popups, module-edit modal redesign, Inspector description → rich editor

Uncommitted at the time of this write-up; committed together with this close-out. Files: `src/renderer/mod/viewer.js`, `src/renderer/mod/connector.js`, `src/renderer/inspector.js`, `src/renderer/hub.js`, `src/renderer/core.js`, `src/renderer/i18n.js`, `style.css`.

- [x] 1. Grouped Obsidian-style filter (`viewer.js`, shared with `connector.js` by load order). New `filterDef` shape: `{groups:[{rules:[...]}]}` — rules within one group are AND'd, groups are OR'd (union) between each other. Four rule fields: `kind` (module type, multi-select of the 15 `MODULE_KINDS`, no operator — a closed enum), `childOf` (this module or its immediate children via a new `filterModuleScope(rootId)` helper — a local 3-line equivalent of `quickswitch.js`'s subtree walk, inlined because `viewer.js`/`connector.js` are eager-loaded while `quickswitch.js` is lazy), `hashtag` and `name` (both get the 5 string operators — is/is not/starts with/ends with/contains — via a shared `strOpMatch(hay,op,needle)`). `parseFilterDef` migrates the old flat `{query,kinds,moduleIds,tag}` shape: `query`→a `name`/`contains` rule and `tag`→a `hashtag`/`is` rule folded into one shared group, with each old `moduleIds[i]` becoming its own additional group (one `childOf` rule each) to preserve the old array's OR semantics; the old item-kind `kinds` checkbox list has no destination field in the new module-kind model and is intentionally dropped, per the plan's own "ประเภทของ module" wording. `applyFilterGroups(items, def, selfModuleId)` replaces the old flat `applySavedFilter`; `loadViewerData`/`loadConnectorData` both call it, unchanged otherwise. No `src/db/viewer.js`/IPC changes — hashtag filtering already worked uniformly across every item kind via `viewerIndex()`'s post-union tag application.
- [x] 2.
