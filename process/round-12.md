## Part 1 — Re-architecture: file splitting + a file-architecture skill (2026-07-26)

Files: `style.css` → `css/` (14), `src/renderer/core.js` → `src/renderer/core/` (12), `src/db/core.js` → `conn.js` + `schema/` (5) + `import-merge.js` + a façade, `src/renderer/hub.js` → `hub/` (7), `navigator.js` → `navigator/` (9), `hero.js` → `hero/` (6); plus `index.html`, `package.json`, `test/onboarding-tour.test.mjs`, `src/renderer/{map,relation,mod/viewer}.js`, `.claude/skills/dracondex-module-style/check.mjs`, and the new `.claude/skills/dracondex-file-arch/`.

The method mattered more than the file list. Every new file is a **verbatim contiguous line range** of the original, emitted in the original order, and the split script refused to write anything until it had concatenated the slices back and matched the source **byte for byte**. That is what makes the two properties this refactor could most easily have broken — CSS cascade order, and the evaluation order of ~90 classic scripts sharing one global scope — unchanged *by construction* rather than by inspection. Where a slice needed a header (`src/db`, which is CommonJS and needs real `require`/`module.exports` wiring), the round-trip check strips the added header/footer before comparing, so the proof still covers every byte of moved code.

- [x] **1.1 `style.css` (3159) → `css/` 14 files**, 39–569 lines each, cut at the file's own `/* SECTION */` banners: `tokens` → `themes` → `base` → `titlebar` → `nav-hub` → `inspector` → `editor` → `layout` → `components` → `legacy-views` → `legacy-tables` → `compat` → `kinds` → `builder`. `index.html` carries 14 `<link>`s in exactly that order, and the order is documented in the file as load-bearing. `package.json`'s `build.files` had `style.css` by name — a packaged build would have shipped with no CSS at all; it now ships `css/**/*`.
- [x] **1.2 `src/renderer/core.js` (2642) → `core/` 12 files**, 105–379 lines: `state` (S, I, the UI_* tables — must parse first, cross-script `const` is in a TDZ until it does), `boot`, `ui`, `settings`, `theme`, `chrome`, `nav`, `pickers`, `views`, `nexus`, `router`, `shortcuts`. No caller outside `index.html` changed, since every function stays a global declaration.
- [x] **1.3 `src/db/core.js` (2532) → 7 files + an 18-line façade.** `conn.js` (the connection adapter and statement cache), `schema/{ddl,indexes,seed}.js` (~1130 lines of pure SQL data), `schema/init.js` (`schemaStamp` + `initDB`), `schema/migrations.js`, `import-merge.js`. The façade re-exports the same five names, so the ~29 files doing `require('./core')` and `database.js` never learned about it. Three deliberate changes rode along: `initDB()` → `initDB(db)` (it was the only function in the file still closing over the module-level `db`; every migration beside it already took a connection); the literal **NUL and `\x01` bytes** in `schemaStamp()`'s separators became escapes — those bytes are why git classified the file as *binary* and suppressed its diff, the same defect class part 2 of the previous plan hit in `wiki.js`; and CRLF → LF, it being the tree's last CRLF file. The `initDB` signature change alters `String(initDB)` and therefore the schema stamp, so an existing database re-runs the idempotent init path exactly once — measured live at 131ms, with the next launch hitting `initDB (skipped, stamp match)`.
- [x] **1.4 `hub.js` (1301) → `hub/` 7 files** (eager `<script>` tags, `kinds.js` first since it owns `MODULE_KINDS`/`KIND_*`), **`navigator.js` (1807) → `navigator/` 9 files** and **`hero.js` (1088) → `hero/` 6 files** (both lazy). The lazy pair needed real plumbing: `loadModule()` injects a `<script>` into `<head>`, which is **async**, so a folder loaded lazily has no intra-group order at all. Added `LAZY_GROUPS` + `loadGroup()` in `core/views.js`, which awaits the whole group with `Promise.all` before the render entry runs, and repointed the five call sites. That is only safe because no file in either group reads another file's binding at top level — the constraint is written down next to `LAZY_GROUPS` rather than left implicit, since it is what a future split there must preserve.
- [x] **1.5 New skill `dracondex-file-arch`** (`SKILL.md` + `check-arch.mjs`). The size half reports `Plan.md`'s bands with an explicit data-file exemption and a "responsibility signal" that prints a long file's banner seams — evidence for a judgement call, never a to-do list. The wiring half hard-fails on what a split breaks *silently*: a renderer file no `<script>` tag or `loadModule()`/`LAZY_GROUPS` reference ever loads, the same top-level name declared in two renderer files, an unlinked or dangling stylesheet, a relative `url()` in `css/` missing its `../`, `build.files` not shipping a source dir, and a `src/db` file unreachable from `database.js`. `dracondex-module-style/check.mjs` was repointed at the new layout at the same time — it now concatenates `css/*.css` and `core/*.js`, and **walks `src/renderer` recursively**, which it never did: `mod/` had been skipped entirely, so its 15 files had never been linted. That is the whole of the 31 → 55 warning move; it is newly-visible pre-existing debt, not new debt, and errors stayed at 0 throughout.

**Four real bugs, three of them pre-existing and none of them the kind a round-trip check can catch:**

- **`url()` resolves against the stylesheet, not the document.** The 33 per-theme `.brand-img content:url('Image/…')` swaps moved into `css/nav-hub.css` and silently became `css/Image/…` — every logo 404'd. Caught only because the app was actually driven and the console showed five `ERR_FILE_NOT_FOUND`; the byte-identical concatenation was perfectly happy. This is now one of the checker's error cases.
- **`flattenModuleTree` was declared *differently* in two eager files** — `hub/menus.js` (recursive, `(nodes, depth, out)`) and `mod/viewer.js` (flat, no arguments). `mod/viewer.js` loads later, so its version won globally and the nest row's "ย้ายไปยัง…" menu threw `Cannot read properties of undefined (reading 'id')`. Confirmed live before the fix (`flattenModuleTree.length` → `0`, `buildMoveToListHtml` throwing) and after (`3`, and the sibling module correctly listed as a move target). viewer's private helper is now `flattenModulesForFilter`.
- **`ensureKonva` was copy-pasted whole into `map.js` and `relation.js`** while four other lazy modules (`mod/locator`, `mod/wanderer`, `navigator/board`, plus map itself) called it and simply hoped one of those two had loaded first. It now lives once, eagerly, in `core/views.js`.
- **`autoExpand` was duplicated** in `map.js` and `timeline.js`; map's copy had no callers at all and is gone.

**Verification.** Electron's binary can't be downloaded in this environment, so everything was driven through `run-dracondex`'s `web-driver.mjs` (real renderer, real preload, real db layer, only Electron's shell stubbed) — stated rather than papered over. The CSS and core splits were checked by **pixel-diffing** the vault and theme-preferences screens against a baseline captured from a `git stash` of the pre-split tree: `0/1024000` pixels different, twice. The db split was exercised both ways — a fresh vault (full `initDB`) and an existing pre-split database (the migration path, then the stamp fast path). The hub/lazy splits were exercised by creating a module, opening it with its Inspector, opening the nest right-click menu and its submenus, all four Sage Hut tabs, and `selectModule('navigator')`/`selectModule('hero')`. `check.mjs` held at **0 errors** throughout, `check-arch.mjs` ends at **0 errors**, and `node --test 'test/*.test.mjs'` passes.

**Deliberately not done:** the 500–1000 line band (`main.js` 817, `writer.js` 830, `builder.js` 820, `db/sync.js` 820, `preload.js` 555, `director.js` 641, `relation.js` 610, `mod/chronicler.js` 575, `mod/narrator.js` 559, `db/wiki.js` 516, `map.js` 507). `Plan.md` puts that band at "check whether it has more than one job", not "split", and splitting `main.js`/`preload.js` additionally breaks `check.mjs`'s IPC-chain parser — a separate blast radius. `check-arch.mjs` now lists all eleven on every run, with their banner seams, so the next round starts from evidence.
